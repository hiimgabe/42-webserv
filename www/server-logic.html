Understanding poll() and handleIncomingConnections()

What is poll()?

poll() is a system call used to monitor multiple file descriptors to see if I/O is possible on any of them.
It's used to handle many client connections simultaneously without using multithreading or blocking I/O.

Each file descriptor is represented by a pollfd struct, which includes:

  • fd: the file descriptor to monitor
  • events: the events to watch for (e.g., POLLIN for read readiness)
  • revents: the events that actually occurred

The syntax: int poll(struct pollfd *fds, nfds_t nfds, int timeout);
Where timeout is the max time (ms) to wait, or -1 to wait indefinitely.

What is POLLIN?

POLLIN is a bitmask flag used with poll() to indicate that data is available to read on a file descriptor. It applies to sockets, files, pipes, etc.

For a listening socket, POLLIN means a new client is trying to connect.
For a client socket, POLLIN means the client has sent data that can be read.

What is POLLOUT?

POLLOUT indicates that the file descriptor is ready for writing — i.e., you can send data without blocking.

This is useful for non-blocking sockets where you want to ensure the socket is ready before attempting to write a response.

What is accept()?

accept() is a system call used on a listening socket to accept a new incoming connection request.

Syntax:
int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen);

- sockfd is the listening socket.
- addr will be filled with the client's address info.
- Returns a new socket file descriptor for communication with the client.

If accept() is successful, you get a new socket connected to the client, which you can then read from or write to.

Function: ConfigParser::handleIncomingConnections()

This function sets up the main server loop that listens for and processes client connections using poll().

Step-by-step Explanation:

  1. Socket setup: For each port at each ServerConfig, it sets up a listening socket and adds it to the poll_fds list.
  2. Main event loop: The server enters a loop that calls poll() repeatedly, waiting for events on the monitored file descriptors.
  3. Handling events:
    • If a listening socket has a POLLIN event, it accepts the new connection using accept().
    • The new client socket is set to non-blocking mode and added to poll_fds for monitoring both POLLIN and POLLOUT events.
    • If a client socket is ready for reading or writing, handleClientRequests is called to process it.
  4. Cleanup: At the end, all sockets are deleted and cleaned up properly.

This architecture allows the server to handle many clients efficiently in a single thread by multiplexing I/O with poll().
